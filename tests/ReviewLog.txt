Log 1 - 10/6/2026: (NOTE: This log has only reviewed the website as seen from
a standard Lenovo Laptop-K0UJR6QD, purchased from RPI. These notes may not
reflect the potential phone experience. RELEVANT FOR FRONTEND!!!)
Website frontend is coming along well. However, I failed to adequately define
certain Accessibility constraints pertaining to color, resulting in some
errors to note. The website's current design forgoes a proper border for the
route selection menu, which immediately creates a color contrast violation
between the menu's color(#FFFFFF) and the overall map(various). More color
contrast violations are found between the subtitle text "ARN Pilot"(--ink-faint)
and the menu color, between the button color and the menu background, and
between the each button's text and the button background. I take the blame for
these mistakes, as I failed to communicate the rules of contrast beyond the
case of text on a background. For the color contrast violations, I suggest
changing the color of the text in each button, as well as adding a border color
that fits the color contrast rules(MAYBE a blue). I am no graphic designer, but
try giving --ink-faint the Hex Value(#050505), and the button
background(#757589). This would fix the color contrast ratios. If you have
specific hues in mind, ensure that there is a 4.5:1 contrast between
--ink-faint and the button backgrounds, as well as between the button
backgrounds and menu(#FFFFFF). To fix my errors, this log entry will be
committed alongside an updated version of Accessibility.txt that not only
explains these constraints better, but makes the rules more navigable by
numbering the list instead of using simple bullet points.

Log 2 - 10/13/2026: Research On Screen Readers.
TL;DR We may need to use multiple to test cross-platform capability.
JAWS - Designed for a Windows PC platform, paid software
    Pros:
        - Highly configurable.
        - Keyboard shortcuts.
    Cons:
        - Memory intensive(can freeze the computer due to RAM)
        - Learning Curve
        - Designed for a Windows PC platform
        - $90 a year
Microsoft Narrator - Bundled with recent Windows OS. Free
    Pros:
        - Easily Available.
    Cons:
        - Limited functionality(particularly with browsers and web apps)
        - Silence on deeper levels of OS(shouldn't matter here)
ChromeVox - Bundled with Chrome laptop/Chrome browser extension. Free
    Pros:
        - Easily available
        - Fairly Navigable
    Cons:
        - Limited to the Chrome platform
VoiceOver - Free, included with Apple Products.
    Pros:
        - No installation or setup required
        - Variety of languages
        - Relatively configurable
        - Keyboard shortcuts
    Cons:
        - Focused on Apple Products
        - Somewhat of a learning curve
NonVisual Desktop Access (NVDA) - Free. Open Source.
    Pros:
        - Supports web content using JavaScript
        - Strong Windows Capability
        - In-built Add-on Store
    Cons:
        - Only supports Windows
        - The How-to's cost money

Log 3 - 10/20/2026: Testing the Website (Frontend and Backend)
My manual testing of the user interface has gathered interesting
results. Chief among them is the overabundance of non-functional
tab interactions. Each pinned location node is accessible via
the tab button, but there is no meaningful interact with those
pins available. This makes navigating the site without a mouse
tedious. I suggest having these pins either inaccessible via tab,
or have the map adjust to center the selected marker on the map.
Regarding map traversal, it is imperative we add a system so that
when the user has not selected part of the user input segment in
the top left, the program will take arrows as map traversal
options. As a quality of life feature, add a button that centers
the map back on campus, similar to the current location button.
Visually, besides my previous comments that haven't been adjusted
for yet, the "show your location" button's symbol doesn't
contrast enough with it's white backdrop, so adjust the symbol's
color as described in Log 1 and Rule 6 of Accessibility.txt.
As a rule of thumb, if a feature or important action seems
inconvient for someone to use without using a mouse or trackpad,
then find a way to make it more convenient.
